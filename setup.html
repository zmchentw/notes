事故：Chocolatey 假性失敗

症狀：安裝 Python 的畫面停在 Installing 64-bit python314... 不動， 隔天早上收到三個套件失敗的紅字。 

Failures
 - python    - Failed to install python because a previous dependency failed.
 - python3   - Failed to install python3 because a previous dependency failed.
 - python314 (exited -1) - Error while running
               'C:\ProgramData\chocolatey\lib\python314\tools\chocolateyInstall.ps1'.

log 拼出來的真實時間軸

  • 前一天 21:54 choco upgrade 開始執行
  • 期間 滑鼠點進主控台視窗 → 進入「選取」模式 → 所有輸出被凍結
  • 02:45:22 [WARN] Chocolatey timed out waiting for the command to finish —— 逾時先觸發了，choco 判定套件失敗
  • 11:53:45 按下 Esc 解除凍結 → [INFO] python314 has been installed. Python 其實安裝成功了
  • 11:53:46 [ERROR] The upgrade of python314 was NOT successful. —— 帳面早就記成失敗，套件被搬進 lib-bad 隔離區

所以這是假性失敗：Python 3.14.7 從頭到尾都裝好了、可以執行、PATH 也設好了、 shim 也建立指向 C:\Python314\python.exe。壞掉的只有 Chocolatey 的登記帳。

修復步驟

  1. 把 C:\ProgramData\chocolatey\lib-bad\python314 備份後移出隔離區
  2. 以管理員權限重新登記，並關掉執行逾時
choco install python3 -y --execution-timeout=0 --no-progress
choco install python  -y --execution-timeout=0 --no-progress

結果：

python|3.14.7
python3|3.14.7
python314|3.14.7

三個套件全部重新登記成功，lib-bad 清空，共 20 個套件零失敗。

關鍵參數

--execution-timeout=0 關閉 Chocolatey 的執行逾時（預設 2700 秒／45 分鐘）。 裝大型套件（Visual Studio、Windows SDK、大型 runtime）時值得加上， 否則慢一點就會被誤判成失敗。

教訓：主控台的「選取」模式

這次事故的唯一根因，是在 Windows 主控台視窗裡點了滑鼠。

在 cmd.exe 或 powershell.exe 的視窗裡點擊或拖曳選取文字， 會讓主控台進入標記／選取模式。這個模式會暫停視窗的所有輸出， 正在輸出文字的程式就會被阻塞，看起來像當機 —— 但它其實是在等你放開。

辨識方式：視窗標題會多出「選取」兩個字。

選取 系統管理員: Windows PowerShell
情況做法
已經卡住了按 Esc（或在視窗內按 Enter）解除，積壓的輸出會一次噴完
預防跑長時間指令時不要在視窗內點滑鼠
要複製文字先讓指令跑完，或改用 Windows Terminal（不會因選取而阻塞輸出）
長工作加大或關閉安裝工具的逾時設定，例如 --execution-timeout=0

附帶問題：MSI 錯誤碼 1618

安裝 GitHub CLI 時第一次失敗： 

Another installation is already in progress. Try again later.
Installer failed with exit code: 1618

1618 = ERROR_INSTALL_ALREADY_RUNNING。 Windows Installer（MSI）同一時間只允許一個安裝作業， 當時 choco 正在裝 Visual Studio 2026 C++ Build Tools 與 Windows SDK，把鎖佔住了。

解法不是重試到死，而是等 MSI 空出來。用一個背景輪詢腳本處理：

$busy = 'vs_install|winsdksetup|vs_setup|^setup$|VSIXInstaller'
while ((Get-Date) -lt $deadline) {
    $running = @(Get-Process | Where-Object { $_.ProcessName -match $busy })
    $choco   = @(Get-Process choco -ErrorAction SilentlyContinue)
    if ($running.Count -eq 0 -and $choco.Count -eq 0) { break }
    Start-Sleep -Seconds 30
}
winget install --id GitHub.cli --exact --silent

PowerShell 5.1 的編碼陷阱

第一版腳本直接掛掉，錯誤是 The string is missing the terminator。 原因是腳本以 UTF-8 無 BOM 寫入，而 Windows PowerShell 5.1 會用系統 ANSI 字碼頁去讀， 中文註解變成亂碼、把引號吃掉，導致語法錯誤。

解法：.ps1 檔要嘛存成 UTF-8 with BOM，要嘛只用 ASCII 內容。 同理，Set-Content / Add-Content 寫檔時要明確加 -Encoding utf8。
